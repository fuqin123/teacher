## 1. 部署方式

Ubuntu 24.04 服务器只需要安装 Docker Engine 和 Docker Compose 插件，不需要安装 Node.js、pnpm、PostgreSQL 或 Caddy。

```text
教师浏览器
   │ HTTPS / HTTP
   ▼
Web 容器（Caddy :80/:443）
   ├─ 静态文件 → Vue 构建产物
   └─ /api/*   → API 容器 :3100
                    │
                    ▼
              API 容器（NestJS）
              启动时自动执行 Prisma 迁移
                    │
                    ▼
          PostgreSQL 16 容器
```

仓库根目录执行：

```bash
docker compose up -d --build
```

即可启动 PostgreSQL、API 和 Web 三个服务。

## 2. 服务器要求

| 项目 | 建议 |
| --- | --- |
| 操作系统 | Ubuntu 24.04 LTS |
| CPU / 内存 | 2 vCPU / 4GB 起步 |
| 磁盘 | 40GB SSD 起步，按备份保留量增加 |
| 网络 | 固定内网 IP 或域名；只开放 SSH、80、443 |
| 软件 | Docker Engine + Docker Compose 插件 |
| 浏览器 | 近两年 Chrome/Edge |

数据库端口默认只绑定到宿主机 `127.0.0.1:5432`，API 端口不发布到宿主机，只允许 Web 容器通过 Docker 内部网络访问。

## 3. 安装 Docker

以下命令使用 root 或具有 sudo 权限的账号执行。

```bash
sudo apt-get update
sudo apt-get upgrade -y
sudo apt-get install -y ca-certificates curl git ufw

sudo apt-get install -y docker.io docker-compose-v2
sudo systemctl enable --now docker

docker --version
docker compose version
```

确认当前账号可以执行 Docker 命令。若提示权限不足，可把可信账号加入 docker 组并重新登录：

```bash
sudo usermod -aG docker "$USER"
```

> Docker 组权限近似 root 权限，只应授予可信账号。

## 4. 获取项目

```bash
cd /opt
sudo git clone "你的仓库地址" scorelens
cd scorelens
```

如果代码已经存在，不要重复克隆，先进入项目目录并检查工作区：

```bash
cd /opt/scorelens
git status
```

## 5. 配置环境变量

复制根目录示例：

```bash
cd /opt/scorelens
cp .env.example .env
chmod 600 .env
nano .env
```

生产配置示例：

```env
POSTGRES_PASSWORD="替换为 openssl rand -hex 24 的结果"
SESSION_SECRET="替换为 openssl rand -hex 32 的结果"
APP_ORIGIN="https://scorelens.example.com"
SITE_ADDRESS="scorelens.example.com"
COOKIE_SECURE="true"
HTTP_PORT="80"
HTTPS_PORT="443"
```

生成随机值：

```bash
openssl rand -hex 24
openssl rand -hex 32
```

变量说明：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | 是 | PostgreSQL 密码；建议使用十六进制随机串，避免 URL 编码问题 |
| `SESSION_SECRET` | 是 | Session 签名密钥；更换后现有登录会话失效 |
| `APP_ORIGIN` | 是 | 教师实际访问的站点 Origin，必须与浏览器地址一致 |
| `SITE_ADDRESS` | 是 | Caddy 站点地址；域名用于自动 HTTPS，`:80` 表示本机 HTTP 测试 |
| `COOKIE_SECURE` | 是 | HTTPS 设为 `true`；仅限本机 HTTP 测试时设为 `false` |
| `HTTP_PORT` | 否 | 宿主机 HTTP 端口，默认 80 |
| `HTTPS_PORT` | 否 | 宿主机 HTTPS 端口，默认 443 |

注意：

- `.env` 已被 Git 忽略，不要提交到仓库。
- `POSTGRES_PASSWORD` 会直接参与数据库连接串，建议只使用十六进制字符。
- 正式环境必须使用 HTTPS，并将 `COOKIE_SECURE` 设为 `true`。
- 不要把数据库密码、Session 密钥写入前端代码。

## 6. 启动全部服务

```bash
cd /opt/scorelens
docker compose up -d --build
```

查看状态：

```bash
docker compose ps
```

查看启动日志：

```bash
docker compose logs -f api web postgres
```

启动过程：

1. PostgreSQL 初始化并通过健康检查；
2. API 镜像构建；
3. API 容器自动执行 `prisma migrate deploy`；
4. API 启动并通过 `/api/v1/health` 健康检查；
5. Web 镜像构建；
6. Caddy 启动、反向代理 API，并通过首页健康检查。

首次构建需要下载基础镜像和依赖，耗时取决于网络。

## 8. 访问与健康检查

域名方式：

```bash
curl -fsS https://scorelens.example.com/api/v1/health
```

本机 HTTP 测试方式：

```bash
curl -fsS http://127.0.0.1/api/v1/health
```

预期：

```json
{
  "status": "ok",
  "service": "scorelens-api",
  "db": "up",
  "timestamp": "..."
}
```

API 不直接暴露到宿主机，只能通过 Web 容器反向代理访问。生产环境不要为了调试额外发布 3100 端口。

## 9. HTTPS 与 Caddy

Caddy 已打包在 Web 镜像中，不需要在宿主机安装。

### 9.1 域名 + 自动证书

服务器满足以下条件时，Caddy 会自动申请和续期证书：

- 域名解析到服务器公网 IP；
- 80/443 端口可访问；
- 安全组和防火墙允许 80/443；
- `.env` 中 `SITE_ADDRESS` 使用域名；
- `APP_ORIGIN` 使用 `https://域名`；
- `COOKIE_SECURE=true`。

证书存储在 `caddy_data` 卷中，容器重建不会丢失。

### 9.2 纯内网 HTTP 测试

如果学校服务器没有公网域名，仅在本机或可信内网测试，可设置：

```env
APP_ORIGIN="http://服务器IP"
SITE_ADDRESS=":80"
COOKIE_SECURE="false"
HTTP_PORT="80"
HTTPS_PORT="443"
```

然后重启 Web 和 API：

```bash
docker compose up -d
```

> `COOKIE_SECURE=false` 仅适用于隔离测试环境。正式环境应使用学校提供的 HTTPS 证书或域名证书。

## 10. 防火墙

确认 SSH 连接正常后：

```bash
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose
```

不要开放 5432 或 3100。数据库虽然只绑定宿主机回环地址，API 也只通过 Docker 内部网络访问，仍建议保持最小暴露面。

## 11. 部署验收

```bash
docker compose ps
curl -fsS https://scorelens.example.com/api/v1/health
```

浏览器检查：

1. 站点跳转登录页；
2. 测试账号登录成功；
3. Cookie `scorelens.sid` 为 `HttpOnly`，生产环境同时为 `Secure`；
4. 班主任、年级主任、任课老师数据范围正确；
5. 上传脱敏 CSV，完成映射、校验和入库；
6. 看板、年级对比、学生档案显示正确；
7. 刷新 `/students/:id` 等深层路由不出现 404；
8. 退出登录后业务页重新跳转登录页。

## 12. 数据持久化

Compose 使用以下命名卷：

| 卷 | 用途 | 删除后果 |
| --- | --- | --- |
| `scorelens-pgdata` 的项目前缀卷 | PostgreSQL 数据 | 学生、考试、成绩全部丢失 |
| `uploads` | 原始导入文件 | 导入历史中的文件丢失 |
| `caddy_data` | HTTPS 证书 | 下次启动重新申请证书 |
| `caddy_config` | Caddy 运行配置 | 通常可自动重建 |

查看实际卷名：

```bash
docker volume ls
```

停止服务但保留数据：

```bash
docker compose down
```

> `docker compose down -v` 会删除命名卷。除非明确要清空所有数据，否则不要使用 `-v`。

## 13. 备份

### 13.1 创建备份目录

```bash
cd /opt/scorelens
mkdir -p backups
chmod 700 backups
```

### 13.2 备份数据库

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
docker compose exec -T postgres pg_dump -U scorelens -d scorelens -Fc \
  > "backups/scorelens-${STAMP}.dump"
```

### 13.3 备份上传文件

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
docker compose exec -T api tar -czf - -C /app/data uploads \
  > "backups/scorelens-uploads-${STAMP}.tar.gz"
```

### 13.4 生成校验文件

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
sha256sum backups/scorelens-${STAMP}.dump \
  backups/scorelens-uploads-${STAMP}.tar.gz \
  > backups/scorelens-${STAMP}.sha256
```

建议每日执行，保留 30 天，并复制到 NAS 或异地。备份未做过恢复验证，不能视为可靠备份。

## 14. 恢复

恢复会覆盖数据库，属于高风险操作。先在维护窗口停止业务写入，并保存当前数据。

### 14.1 停止 API 和 Web

```bash
docker compose stop api web
```

### 14.2 恢复数据库

```bash
docker compose exec -T postgres pg_restore \
  -U scorelens -d scorelens --clean --if-exists \
  < backups/scorelens-YYYYMMDD-HHMMSS.dump
```

恢复到空库时可省略 `--clean --if-exists`。

### 14.3 恢复上传文件

```bash
docker compose run --rm --no-deps --entrypoint tar api -xzf - -C /app/data \
  < backups/scorelens-uploads-YYYYMMDD-HHMMSS.tar.gz
```

### 14.4 启动并验证

```bash
docker compose start api web
docker compose ps
curl -fsS http://127.0.0.1/api/v1/health
```

按四类角色重新登录回归，并抽查导入文件、考试和成绩。

## 15. 升级

### 15.1 升级前

1. 备份数据库和上传文件；
2. 记录当前版本：`git describe --tags --always`；
3. 阅读目标版本更新说明；
4. 确认 `.env` 未被覆盖。

### 15.2 拉取并重建

```bash
cd /opt/scorelens
git status --short
git pull --ff-only
docker compose build api web
docker compose up -d
```

API 容器每次启动都会执行 `prisma migrate deploy`，因此无需在宿主机安装 Prisma CLI。

### 15.3 验证

```bash
docker compose ps
docker compose logs --tail 100 api
curl -fsS https://scorelens.example.com/api/v1/health
```

### 15.4 回滚

1. 停止写入；
2. 恢复升级前数据库备份；
3. 切回上一版本代码；
4. 重新构建并启动镜像；
5. 完整验证登录、导入和分析。

数据库迁移可能无法通过代码回滚撤销，因此数据库备份是回滚的前提。

## 16. 常用运维命令

```bash
# 查看状态
docker compose ps

# 查看全部日志
docker compose logs -f

# 查看 API 日志
docker compose logs -f api

# 重启 API
docker compose restart api

# 重启全部服务
docker compose restart

# 重新构建并启动
docker compose up -d --build

# 停止但保留数据
docker compose down

# 查看资源占用

```

## 17. 故障排查

| 现象 | 优先检查 | 处理 |
| --- | --- | --- |
| API 容器反复重启 | `docker compose logs api` | 检查迁移、`DATABASE_URL`、数据库密码和健康检查 |
| Web 502 | API 容器状态 | 等待 API 健康，确认 `api:3100` 可解析 |
| 页面打开但接口失败 | 浏览器 Network、`APP_ORIGIN` | Origin 必须与访问地址完全一致 |
| 登录后立即退出 | HTTPS、`COOKIE_SECURE` | 生产使用 HTTPS + `COOKIE_SECURE=true` |
| HTTP 测试无法登录 | Cookie Secure | 仅本机测试设置 `COOKIE_SECURE=false` |
| 证书申请失败 | 域名解析、80/443、防火墙 | 放行端口并确认域名指向服务器 |
| 数据库连接失败 | `docker compose logs postgres` | 检查密码、卷状态和 PostgreSQL 健康状态 |
| 构建失败 | Docker 日志、lockfile | 使用仓库锁文件，清理旧镜像后重建 |
| 上传文件丢失 | `uploads` 卷 | 确认没有执行 `down -v`，从备份恢复 |
| 磁盘持续增长 | 数据库、上传文件、备份 | 制定保留策略并检查容器日志大小 |

进入数据库排查：

```bash
docker compose exec postgres psql -U scorelens -d scorelens
```
