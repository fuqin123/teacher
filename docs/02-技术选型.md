## 1. 选型原则

1. **可维护**：代码结构清晰、类型完整、升级路径明确，避免"只有原作者能改"。
2. **单语言**：前后端统一 TypeScript，接口契约用 Zod 共享，减少两套模型漂移。
3. **少基础设施**：数据库就是一个 SQLite 文件，不引入 Redis、消息队列、对象存储，教师本机无需安装数据库服务。
4. **性能可解释**：每个页面能明确说出查询和缓存路径，切页不等待。
5. **AI 可降级**：AI 是增强项，关闭或故障时手动映射仍可完整工作。
6. **可替换**：AI 服务商、文件存储、UI 组件库都通过接口/配置隔离，不做深度绑定。
7. **本地优先**：开发直接使用本地 SQLite 文件，演示与校内部署用同一套 Docker Compose，两者数据库结构与迁移脚本完全一致。

## 3. 前端

### 3.1 框架与构建

- **Vue 3 + Vite + TypeScript（strict）**。
- 原型是单文件 HTML + 自定义 CSS + ECharts，Vue 的模板语法和组件拆分与它最接近；设计师给出的设计令牌可以直接落到 CSS 变量。
- 按路由懒加载页面；构建产物由 Caddy/Nginx 托管。
- `vue-tsc` 做类型检查，纳入 CI。

### 3.2 状态与数据获取

- **Pinia** 只负责：当前用户/角色、当前考试、当前班级、侧边栏折叠等客户端状态。
- **@tanstack/vue-query** 负责所有服务端数据：
  - 缓存键包含 `examId`、`classId`、`studentId`。
  - `staleTime` 5 分钟，`gcTime` 30 分钟，避免切页重复请求。
  - 使用 `placeholderData: keepPreviousData` 在筛选变化时保留上一份数据。
  - 导入/撤销/更正后精确失效对应考试。
- 筛选条件写入 URL query，刷新和分享可复原。
- 顶部全局考试选择器切换时，统一失效/重取当前页数据；避免每个组件各自监听。

### 3.3 UI 与图表

- **Element Plus** 用于表单、下拉、日期、弹窗、分页、上传等交互件；视觉通过 CSS 变量覆盖：
  - 主色 `--el-color-primary: #3B7CFF`
  - 圆角、字体、边框颜色对齐原型设计令牌。
- 看板卡片、KPI、排名表等强设计感区域使用自定义组件，不完全套用组件库默认样式。
- 样式体系以原型设计令牌（CSS 变量）为基础，页面使用原生 CSS/SCSS；首版不引入 Tailwind，避免与 Element Plus 主题形成两套样式体系。若后续自定义组件明显增多，再评估 UnoCSS/Tailwind。
- **ECharts 按需引入**：只注册 Bar/Line/Radar/Heatmap 等实际使用的图表，避免整包约 1MB。
- 图表封装为 `ChartBox`：
  - 挂载时 `init` 一次，`ResizeObserver` 处理容器变化。
  - 卸载时 `dispose`，防止内存泄漏。
  - 数据更新使用 `setOption(option, { notMerge: false })`，避免整图重建。
  - 统一主题：配色、坐标轴、tooltip 对齐原型。
- 创建/编辑表单使用 Element Plus 校验 + 共享 Zod schema 做提交前校验；不重复写两套字段定义。

### 3.4 性能约定

- 页面首屏最多 1 个主聚合请求 + 0~1 个分页请求。
- 排名/学生列表分页，默认 20~50 条；不做一次性全量渲染。
- 骨架屏、错误重试、空状态必备；导入操作展示进度和结果。
- 路由切换保留旧数据，避免"白屏等待"。
- 生产构建后测量：首屏 JS gzip 目标 < 400KB（不含按需图表 chunk），切页可交互 < 300ms。
- 不在前端做排名/汇总等业务计算，所有数字来自 API。

### 3.5 兼容性

- 桌面优先，最小 1366×768；< 1100px 栅格降为单列。
- 支持 Chrome/Edge 近两年版本及主流 Chromium 内核浏览器；不支持 IE。
- 文件上传兼容 WPS 导出的 `.xlsx` / `.xls` / `.csv`。

## 4. 后端

### 4.1 框架与结构

- **NestJS + Express adapter**：模块化、DI、Guard、Interceptor 完整，适合长期维护；Express adapter 对 Session 中间件兼容最好。
- 模块划分：`auth`、`roster`、`exams`、`imports`、`analytics`、`settings`、`audit`。
- 每个模块内部分层：controller（HTTP）→ service（用例）→ repository（数据）。
- 领域规则（排名、阈值、校验）放在纯函数/domain service，便于单测。
- 全局异常过滤器统一错误结构；全局 ValidationPipe 使用 Zod schema。
- Swagger 自动生成 OpenAPI；生产环境限制访问。

### 4.2 数据访问

- **Prisma** 负责实体 CRUD、关系查询、迁移。
- **统计查询用参数化 SQL**（`$queryRaw`），原因是窗口函数、CTE、聚合在 SQL 中更直接；用 Zod 校验返回结构。
- 禁止在循环中查数据库；列表查询用 `select` 明确字段，避免 N+1 和大对象。
- 事务边界：
  - 导入提交：批次锁 + 成绩 upsert + 变更日志 + 汇总重建，同一事务。
  - 撤销/更正：变更日志回放 + 汇总重建，同一事务。
- Prisma 迁移：开发用 `migrate dev`，生产用 `migrate deploy`；种子脚本生成演示数据。

### 4.3 认证与安全

- `express-session` + 自建 Prisma 会话存储（`prisma-session.store.ts`），会话存同一个 SQLite 文件；无需 Redis，也无需 `connect-sqlite3` / `better-sqlite3` 等原生依赖。
- Cookie：`HttpOnly`、`SameSite=Lax`、生产 `Secure`；8 小时滚动过期。
- Argon2id 哈希密码；登录失败 5 次锁定 30 分钟（可配置）。
- `@nestjs/throttler` 保护登录、上传、AI 建议接口。
- 写请求校验 `Origin`/`Referer`；所有权限在 service 层校验数据范围。
- 文件上传：Multer 限制大小，UUID 重命名，存非 Web 根目录；下载走鉴权接口。
- 审计：导入、撤销、更正、权限变更、设置修改全部落 `audit_logs`。

### 4.4 导入与 AI 适配

- 解析器独立为 `ExcelParserService`，输入文件、输出标准网格 + 表头候选，纯函数为主，便于测试。
- 映射器分三级：规则词典 → 映射模板 → AI。AI 通过 `AiMappingProvider` 接口调用，方便替换服务商或关闭。
- 校验器独立为 `ImportValidator`，规则表驱动；错误定位到行/列。
- 入库由 `ImportCommitService` 编排，严格事务；汇总重建由 `SummaryRebuildService` 负责。
- AI 调用：
  - `openai` SDK，配置 `baseURL` / `model` / `apiKey`。
  - JSON 输出模式，`temperature=0`，超时 25 秒，失败重试 1 次。
  - 只发送表头 + 脱敏样例；日志记录耗时/token，不记录完整数据。
  - 失败返回明确错误码，前端切换手动映射，不阻塞流程。

### 4.5 日志与可观测性

- pino 结构化日志：requestId、用户 ID、路径、状态码、耗时。
- 慢查询日志：开发 > 100ms，生产 > 500ms。
- 导入专项日志：批次 ID、行数、映射来源、AI 耗时、校验统计、入库耗时。
- `/api/v1/health` 检查进程与数据库。
- 可选接入 Sentry；首版以日志 + 健康检查为主。

## 5. 数据库

### 5.1 为什么是 SQLite

- **使用范围明确**：当前按“一位教师、一个班级”使用，成绩数据总量在万级，单个 SQLite 文件完全覆盖，不需要独立数据库服务。
- **降低教师端负担**：教师本机不需要安装 PostgreSQL、Docker 或任何数据库管理工具，`pnpm install` 后即可运行；数据库就是 `apps/api/data/scorelens.db` 一个文件。
- **备份与迁移简单**：`VACUUM INTO` 生成一致性快照即完成备份，换机器时复制文件即可；恢复不需要 `pg_restore` 之类的工具链。
- **统计能力足够**：排名、及格率、分数段等聚合在应用层完成（`analytics.calculations.ts` 纯函数），不依赖窗口函数与 CTE；SQLite 的索引与事务能力足以支撑单班查询。
- **Prisma 支持完整**：`Decimal`、`Json`、枚举在 SQLite 下均由 Prisma 映射（枚举与 JSON 落库为 TEXT），迁移、Studio、`migrate deploy` 行为与 PostgreSQL 一致。

### 5.2 约定

- 主键统一 UUID（应用层 `uuid()` 生成），避免自增 ID 被枚举。
- 分数与满分使用 Prisma `Decimal`（SQLite 中为 NUMERIC 亲和类型）；比率存小数（0~1），展示时转百分比；计算结果统一 `round(value, 1)`。
- 时间以 `DATETIME` 存储，应用层统一 `Asia/Shanghai`；日期字段不再使用数据库原生 date 类型。
- 所有外键建索引；高频过滤列建组合索引。
- 迁移只前进；破坏性变更分两步（先加列/双写，再删旧列）。
- 汇总表是派生数据，提供管理员“重建汇总”命令；禁止手工改。
- SQLite 不支持的写作方式：`TRUNCATE`、`mode: 'insensitive'`、`jsonb` 操作符、`timestamptz`。种子脚本改为按外键顺序 `deleteMany`，模糊查询依赖 SQLite `LIKE` 的默认 ASCII 不区分大小写行为。

### 5.3 何时需要换回 PostgreSQL / MySQL

- 多个班级、多位教师同时在线写入（并发写是 SQLite 的短板，单写者模型会串行化）。
- 需要多实例部署或数据库与 API 分离。
- 数据量进入十万级以上、需要窗口函数与物化汇总表。

出现上述需求时，Prisma schema 只需改 `provider` 与原生类型（`@db.Decimal`、`@db.Date`），业务代码基本不动。

## 6. AI 服务

### 6.1 选型

- **国内 OpenAI 兼容 API**（DeepSeek / 通义 / 智谱等），通过 `baseURL + model` 配置切换；v0.5.0 已按此方案落地（内置 `fetch`，未引入 SDK）。
- 不引入 LangChain 等编排框架：单次结构化映射调用，直接用官方 SDK 更透明、可控。
- 只用于"表头/结构映射建议"和"考试元信息提取"；不做分数计算、不做整表转换。

### 6.2 调用策略

| 项 | 策略 |
| --- | --- |
| 触发条件 | 规则与映射模板仍有未识别列 |
| 输入 | 表头、sheet 名、文件名、最多 3 行脱敏样例 |
| 输出 | 固定 JSON（映射、置信度、考试元信息、警告） |
| 温度 | 0 |
| 超时 | 25 秒 |
| 重试 | 1 次（仅网络/5xx） |
| 失败降级 | 返回手动映射界面，导入继续 |
| 缓存 | 表头指纹命中模板不再调用 |
| 成本 | 每种新格式约 1~2k tokens，可忽略；记录用量 |
| 隐私 | 姓名/学号脱敏；不发送完整名单；API Key 仅服务端 |

### 6.3 提示词与版本

- 提示词模板放代码仓库（`imports/ai/prompts/`），带版本号。
- 输出必须通过 Zod schema 校验；不合法则重试一次，仍失败转手动。
- 模型返回的"满分"仅作为建议，最终以考试科目配置为准；用户必须确认。
- 置信度只做 UI 提示，不作为自动入库依据。

## 7. 部署与运维

### 7.1 开发环境（Windows）

- 不需要 Docker Desktop 与 WSL2：SQLite 是文件数据库，`pnpm dev` 即可跑通前后端。
- 本地启动：
  - `pnpm typecheck`
  - `pnpm --filter @scorelens/api prisma:migrate`（首次或迁移变更后）
  - `pnpm dev`
- 需要从零重建演示数据时执行 `pnpm db:seed`；需要清空数据库时删除 `apps/api/data/scorelens.db` 后重新迁移即可。
- Node 24 LTS，pnpm 管理依赖。
- 测试/验收以 Ubuntu 24.04 为准（见 7.3）；Windows 仅承担开发与本地调试。

### 7.2 本地完整演示

```text
docker compose up -d --build
# web:     http://localhost
# api:     http://localhost/api/v1
# db:      app_data 卷内的 scorelens.db，不发布任何端口
```

- 种子数据：3 个班、42 名学生、3 场考试、630 条成绩，登录即可看到原型效果。
- 数据库文件与上传文件统一挂载到 `app_data` 卷，容器重建不丢数据。

### 7.3 测试与正式部署（Ubuntu 24.04）

| 环境 | 操作系统 | 运行时 | 用途 |
| --- | --- | --- | --- |
| 开发 | Windows 11 | Node 24 + pnpm（本地 SQLite 文件） | 本机开发、热更新 |
| 测试 | Ubuntu 24.04 LTS | Docker Engine + Compose | 联调、验收、回归 |
| 正式 | 待定（Ubuntu 24.04 基线） | Docker Compose + Caddy | 校内服务器/云主机 |

- 测试环境：2 vCPU / 4GB / 40GB 起步；安装 Docker Engine（官方源）与 Compose 插件；时区 `Asia/Shanghai`；只开放 80/443。
- Docker Compose：`api` + `web`（Caddy 反代 + 静态资源）+ 备份任务；SQLite 文件存放于 `app_data` 卷，不暴露任何数据库端口。
- Caddy 自动 HTTPS；纯内网可 HTTP + 网络访问控制。
- 每日备份：`pnpm db:backup`（SQLite `VACUUM INTO` 快照）+ 上传文件归档，保留 30 天，建议异地/网盘再存一份。
- 发布前备份；`prisma migrate deploy`；健康检查通过再切流量；保留上一版镜像回滚。
- 测试环境使用演示/脱敏数据，不直接使用正式学生数据。
- Windows 与 Linux 差异：文件名统一小写、路径用 `path.join`、换行交给 Git 处理；文件系统大小写和文件锁行为以 Ubuntu 24.04 为准，发布前必须在测试环境跑完整导入链路。

### 7.4 环境变量

见《项目架构》11.3。所有密钥只通过环境变量注入，不写入仓库、不返回给前端。

## 8. 工程规范

- TypeScript `strict: true`；禁止 `any` 作为偷懒手段。
- ESLint 9 + Prettier；提交前 lint-staged。
- 命名：
  - 数据库 `snake_case`；TS `camelCase`；类型 `PascalCase`；常量 `UPPER_SNAKE_CASE`。
  - API 路径复数名词：`/students`、`/exams`、`/imports`。
- 错误码集中定义（`IMPORT_*`、`AUTH_*`、`PERMISSION_*`），前端按码处理。
- 共享契约：
  - Zod schema 放 `packages/shared`。
  - API 响应用 Zod 解析后再交给前端，避免字段漂移。
- 测试：
  - 纯函数（口径、排名、校验）必须有单测。
  - 导入流水线必须有真实脱敏 fixture 的集成测试。
- 提交规范：Conventional Commits；每个 PR 聚焦一个模块。
- 文档：本三份文档随架构变更更新；数据库变更加迁移说明。
- 依赖：锁定版本；每月检查一次升级；升级后跑完整测试。

## 9. 备选方案与取舍

| 备选 | 优点 | 不选原因 |
| --- | --- | --- |
| React + Fastify | 生态大、后端轻 | 原型是 HTML/CSS，Vue 迁移更直接；NestJS 结构更适合多模块长期维护 |
| Next.js 全栈 | 一体化、SSR | 内部管理后台不需要 SSR/SEO；认证与 API 拆分更清晰 |
| FastAPI + pandas | Excel/统计处理强 | 需要维护 Python + TS 两套语言与工程规范；当前 Node 解析足够 |
| Drizzle ORM | SQL 更透明、轻量 | Prisma 迁移/Studio/文档更适合学校场景的维护者；统计仍可用原生 SQL |
| MySQL | 学校环境常见 | 仍需独立数据库服务，单班本机部署不划算 |
| PostgreSQL | 统计与并发能力更强 | 需要独立服务与运维，与“教师本机零安装”的目标冲突；规模扩大后再作为迁移目标 |
| JWT 无状态鉴权 | 易扩展 | 无法即时撤销；需要额外刷新/黑名单，学校场景 Session 更简单 |
| Redis + BullMQ | 异步任务成熟 | 首版导入同步足够；多一个基础设施就多一份运维负担 |
| MinIO/S3 | 文件共享、扩展 | 单机部署本地卷足够；StorageService 已预留替换点 |
| Element Plus 全家桶 | 开发快 | 看板视觉定制强，核心卡片/图表仍自定义，避免"组件库默认风" |
| 全量引入 ECharts | 简单 | 包体大、首屏慢；按需引入成本很低 |

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 学校 Excel 格式极其混乱 | 解析失败/映射错误 | 规则词典 + 映射模板 + AI + 人工确认；用真实脱敏文件建 fixture 回归 |
| AI 返回不稳定/幻觉 | 映射错误 | 只接受结构化 JSON + Zod 校验；置信度提示；必须人工确认；AI 不碰分数 |
| AI 服务不可用/超时 | 导入受阻 | 自动降级手动映射；设置页显示状态；超时/重试有上限 |
| Prisma N+1 / 查询慢 | 切页卡顿 | 列表 `select` 明确字段；统计走汇总表/原生 SQL；慢查询日志；性能预算 |
| 汇总重算遗漏 | 数字不一致 | 所有写成绩路径统一调用 `SummaryRebuildService`；提供重建命令；集成测试校验 |
| SheetJS 版本/许可证 | 依赖风险 | 锁定版本并记录许可证；必要时改用 LibreOffice 转换 + exceljs 读取 |
| 单机文件存储 | 扩容/迁移麻烦 | 本地卷 + StorageService 抽象；多实例前迁 MinIO |
| SQLite 单写者 | 多人同时导入时写入串行 | 当前为单教师单班使用，写入量极小；并发场景改为 PostgreSQL（Prisma 只改 provider） |
| Session 存库 | 多实例需共享库 | 首版单实例；多实例时改用 PostgreSQL 并共享 `user_sessions` 表 |
| 单维护者风险 | 交接困难 | 三份文档 + 测试 + 迁移脚本 + 统一目录结构；关键决策写 ADR |
| 学生隐私 | 合规风险 | 最小化数据、AI 脱敏、导出审计、权限范围、备份访问控制 |

## 11. 版本与升级策略

- Node.js 24 LTS；SQLite 由 Prisma 内置驱动提供，无需单独安装；其余依赖取创建脚手架时的最新稳定版。
- 使用 `pnpm-lock.yaml` 锁定；CI 使用 `--frozen-lockfile`。
- 升级节奏：每月一次小版本；大版本（Vue/NestJS/Prisma）单独评估，先在本地/测试环境跑回归。
- 数据库迁移随版本发布；发布前执行 `pnpm db:backup`；回滚依赖上一版代码 + SQLite 快照。
- 每季度验证一次备份恢复。

## 12. 选型结论

首版采用：

**Vue 3 + TypeScript + Vite + Element Plus + ECharts + Vue Query（前端）**
**NestJS + Prisma + SQLite + Zod（后端）**
**SheetJS 读表 + exceljs 导出 + OpenAI 兼容 AI 映射**
**Docker Compose + Caddy 部署：Windows 本机以本地 SQLite 文件开发，Ubuntu 24.04 用同一套 Compose 测试，数据落在持久化卷内。**

这套组合的共同点是：单语言、少基础设施、查询路径透明、AI 可降级，直接针对"格式多、要维护、切页不能卡"的三个核心约束。
