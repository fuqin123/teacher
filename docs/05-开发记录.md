## 3. 需求与关键决策

### 3.1 已确认需求

1. 面向班主任、任课老师、年级主任，核心是成绩导入后的可视化分析。
2. 支持月考、期中、期末及历史考试，文件格式可能不统一。
3. 及格率、优秀率默认按 60%、80% 计算。
4. 每个科目在每场考试中的满分可配置，不硬编码地区总分。
5. 缺考科目不参与总分排名；单科统计剔除缺考。
6. 考试随班主任或年级主任导入时创建或确认，不要求预先编排考试。
7. 任课老师默认只读，只能查看所教班级和本科目数据。
8. 首版聚焦初中文化科目，体育、会考、实验操作等后续扩展。
9. 导入撤销窗口目标为 24 小时，但撤销功能尚未实现。
10. 后续接入国内 OpenAI 兼容 API 做表头映射建议，AI 不直接修改分数。

### 3.2 已落地决策

| 决策 | 实际选择 | 原因 |
| --- | --- | --- |
| 工程结构 | pnpm monorepo | 前后端共享 TypeScript 类型和 Zod 契约 |
| 后端 | NestJS + Prisma | 模块边界清楚，迁移和事务能力强 |
| 数据库 | SQLite（本地单文件） | 单班数据量小，教师本机零数据库安装；备份即复制文件 |
| 登录态 | HttpOnly Session Cookie + SQLite 会话表（Prisma 会话存储） | 可撤销，不引入 Redis 与额外原生驱动 |
| 成绩模型 | `exam × student × subject` 长表 | 科目扩展无需改表 |
| 考试科目满分 | 保存到 `exam_subjects` | 不同地区、不同考试可分别配置 |
| 导入确认 | 规则建议 + 人工映射 + 服务端复核 | 即使没有 AI 也能完整导入 |
| 统计方式 | 当前按需计算 | 先保证正确性和可维护性，汇总表后续优化 |
| UI 组件 | 项目内自定义 `AppSelect` | 与现有主题一致，避免为下拉引入整套组件库 |
| 动画 | ECharts 统一封装 + reduced-motion | 保持展示效果，同时照顾系统减弱动效设置 |

## 5. 实际实现说明

### 5.1 仓库结构

```text
teacher/
├─ apps/
│  ├─ api/                 NestJS API、Prisma、种子脚本
│  └─ web/                 Vue 3 SPA
├─ packages/
│  └─ shared/              共享类型、Zod schema、常量、表头同义词
├─ docs/                   架构、选型、功能、版本、开发、部署文档
├─ prototype/              视觉原型
├─ docker-compose.yml      API + Web/Caddy 服务（SQLite 数据在 app_data 卷）
├─ docker/                 Caddy 容器配置
├─ apps/api/Dockerfile     API 多阶段镜像
├─ apps/web/Dockerfile     Web 多阶段镜像
└─ pnpm-workspace.yaml
```

### 5.2 数据模型

核心表：

- `users`、`user_roles`：账号与角色；
- `academic_terms`、`grades`、`class_groups`、`classes`：学期与组织；
- `students`、`student_term_enrollments`：学生档案和学期分班；
- `subjects`、`exam_subjects`：科目及考试满分配置；
- `exams`：年级共享的考试记录；
- `scores`：成绩长表，唯一键为 `(exam_id, student_id, subject_id)`；
- `import_batches`：文件、映射、校验、统计快照；
- `score_change_logs`：成绩写入和覆盖日志；
- `audit_logs`：操作审计；
- `app_settings`：后续设置项预留；
- `user_sessions`：登录会话，由 API 内置的 Prisma 会话存储维护。

成绩同时保存考试当时的 `class_id`，避免学生调班后历史班级统计发生变化。

### 5.3 认证与权限

- 密码使用 Argon2id 哈希。
- Session 存 SQLite（`user_sessions`），Cookie 为 `HttpOnly + SameSite=Lax`。
- HTTPS 生产环境设置 `COOKIE_SECURE=true`；仅隔离 HTTP 测试环境可设为 `false`。
- 管理员可查看全部数据。
- 年级主任按所负责年级访问。
- 班主任按所带班级访问全部科目。
- 任课老师按“班级 × 科目”访问，响应只返回本科数据。

权限在服务层校验，不依赖前端隐藏菜单。

### 5.4 数据库：改为本地 SQLite（v0.4.0）

v0.3.0 及之前使用 PostgreSQL + Docker Compose。考虑到当前实际范围是“一位教师、一个班级”，数据量在万级以内，独立数据库服务对教师本机是纯负担。v0.4.0 做了以下改造：

1. **Schema**：`provider` 由 `postgresql` 改为 `sqlite`；去掉 `@db.Decimal`、`@db.Date` 等 PG 原生类型；枚举与 `Json` 字段在 SQLite 下落为 TEXT，由 Prisma 负责序列化。
2. **迁移**：删除旧的 PostgreSQL 初始化迁移，重建 `20261124033022_init_sqlite`；开发用 `prisma migrate dev`，容器启动用 `prisma migrate deploy`。
3. **数据位置**：开发为 `apps/api/data/scorelens.db`（相对 `prisma/` 目录解析），容器内为 `/app/data/scorelens.db`，与上传文件共用 `app_data` 卷。
4. **会话存储**：移除 `connect-pg-simple` 与 `pg`，新增 `PrismaSessionStore`（`apps/api/src/common/prisma-session.store.ts`），把会话写入 `user_sessions` 表，避免再引入 `connect-sqlite3` / `better-sqlite3` 等原生依赖；进程内每 30 分钟清理过期会话。
5. **种子脚本**：`TRUNCATE ... RESTART IDENTITY CASCADE` 改为按外键顺序 `deleteMany` 事务。
6. **备份**：新增 `pnpm db:backup`，用 SQLite `VACUUM INTO` 生成一致性快照到 `apps/api/backups/`。
7. **编排**：`docker-compose.yml` 去掉 `postgres` 服务与 `POSTGRES_PASSWORD`，改为 `app_data` 单卷持久化。

改造过程中确认的 SQLite 约束：`mode: 'insensitive'` 不可用、没有 `TRUNCATE`、没有原生 `decimal`/`date`/`jsonb`、同一时刻只有一个写者。业务代码已按这些约束调整，接口与页面行为保持不变。

### 5.5 导入流水线

当前实际流程：

```text
上传文件
  → SheetJS 解析第一个工作表
  → 前 20 行定位表头
  → 同义词生成映射建议
  → 人工确认学号、姓名、科目和满分
  → 服务端校验
  → 事务创建/复用考试、写成绩、写变更日志
  → 更新导入批次
```

当前限制：

- 只读取第一个 sheet；
- 支持 `.xlsx`、`.xls`、`.csv`；
- 单文件不超过 10MB、5000 行、100 列；
- 空白成绩会报错，必须补录或填写缺考标记；
- 当前没有 AI 映射、模板复用、撤销和成绩更正 UI；
- 重复导入会覆盖同一“学生 × 科目”成绩并写变更日志，尚无独立的重复策略界面。

### 5.6 分析口径

- 总分只加入 `included_in_total=true` 的科目。
- 任一计入科目缺考时不计算总分，不参与总分排名。
- 排名采用并列名次、下一名跳号，例如 1、1、3。
- 单科平均分和及格/优秀率只统计有有效成绩的学生。
- 名次变化与所选考试的上一场考试比较，不是固定取最后两场。
- 当前看板、年级对比和学生档案由后端按需计算，尚未使用汇总表。

### 5.7 前端状态与组件

- Pinia 保存用户和全局筛选上下文。
- Vue Query 管理服务端数据，`staleTime=5min`、`gcTime=30min`。
- 登录和退出时清空 Query 缓存，防止不同账号复用旧数据。
- `AppSelect` 支持搜索、键盘导航、提示文字、选中态和 Teleport 浮层。
- `EChart` 统一图表动画、骨架屏、尺寸监听和资源释放。
- 学生列表支持按姓名、学号、班级快速定位并直接进入档案。

## 6. 问题与修复记录

| 问题 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| pnpm 忽略依赖构建脚本 | Prisma/esbuild 未正常准备 | pnpm 12 的构建脚本白名单机制 | 在 `pnpm-workspace.yaml` 增加 `allowBuilds` |
| Prisma 关系不完整 | `Score.changeLogs` 报错 | 声明了没有反向关系的字段 | 删除未使用的关系字段 |
| 3000 端口被占用 | API 无法启动 | Docker Desktop 占用端口 | API 改为 3100，同步修改 Vite 代理 |
| 退出登录返回 500 | 种子重置后旧会话退出失败 | 审计记录关联已删除用户 | 审计写入失败只记日志，不阻断认证主流程 |
| 切换账号看到旧数据 | 任课老师看到上班主任的总分和全部科目 | Vue Query 缓存跨用户复用 | 登录/退出清空缓存，布局挂载时强制重载上下文 |
| 单科表格重复列 | “本科成绩”和“数学”重复 | 单科模式仍渲染全部科目列 | 仅完整模式渲染多科成绩列 |
| KPI 对比考试错误 | 选择历史考试时仍与最后两场比较 | 固定使用趋势数组最后两项 | 按当前考试 ID 找上一场 |
| 图表动画被吞 | 图表直接显示终态 | 初始 ResizeObserver 回调触发 resize | 尺寸变化超过 1px 才 resize |
| 名次轴出现小数 | 显示 1.0、1.2 等刻度 | ECharts 自动选择小数间隔 | 固定整数范围、`minInterval=1` |
| 数据库不可用 | 登录和 `/auth/me` 500 | v0.3.0 为 PostgreSQL 容器停止；v0.4.0 起为 SQLite 文件被删除或目录无写权限 | 重启容器并检查 `app_data` 卷；健康接口始终校验数据库连通 |
| SQLite 下的迁移与种子失败 | `TRUNCATE ... CASCADE` 报语法错误，`mode: 'insensitive'` 不被支持 | SQLite 不支持 PG 专属语法与查询参数 | 种子改为按外键顺序 `deleteMany`；搜索移除 `mode`，依赖 SQLite `LIKE` 的默认大小写行为 |
| Prisma 引擎文件被占用 | `prisma generate` 报 `EPERM: rename query_engine-windows.dll.node` | 旧的 `pnpm dev` 进程仍加载引擎 DLL | 先停止 API 开发进程再执行 `prisma generate` |
| SQLite 不支持原生类型 | schema 校验报 `Native type Decimal/Date is not supported for sqlite connector` | `@db.Decimal`、`@db.Date` 属于 PG 原生类型 | 去掉 `@db.*`，保留 Prisma `Decimal` 标量与 `DateTime` |
| Docker 构建访问 Debian 软件源失败 | API 镜像在 `apt-get` 阶段中断 | 构建容器无法访问 `deb.debian.org` | 移除镜像内 apt 安装，直接使用 Node 官方基础镜像 |
| Caddy 配置格式警告 | Web 启动日志提示 Caddyfile 未格式化 | 缩进不符合 `caddy fmt` 规则 | 统一使用制表符并重新构建验证 |

## 8. 已知限制

1. 尚无自动化单元测试和集成测试，当前主要依赖类型检查、构建和人工浏览器回归。
2. AI 表头映射尚未实现。
3. 映射模板、24 小时撤销、成绩更正尚未实现。
4. 只读取工作簿第一个 sheet。
5. 基础数据页面当前为只读，账号和名单维护仍依赖种子或数据库工具。
6. 分析按需计算，大规模历史数据下需要汇总表和索引优化。
7. 尚无导出、打印和审计日志查看界面。
8. 已提供 API + Web/Caddy 全栈 Compose（SQLite 数据卷），但 Ubuntu 24.04 实机验收仍需按部署文档逐项执行。
9. 数据库按单班本机使用设计，多人并发写入或多实例部署前需要迁移到 PostgreSQL。
10. API 镜像包含构建和迁移所需依赖，后续可继续拆分迁移服务并缩减运行时镜像体积。

## 10. 日常开发约定

- 修改共享接口时同步更新 `packages/shared` 和调用方。
- 数据库变更必须新增 Prisma migration，不直接修改已执行迁移。
- 导入、统计、排名等核心规则优先放纯函数，并补测试。
- 提交前至少运行 `pnpm typecheck` 和 `pnpm build`。
- 涉及导入或权限的改动必须做角色回归。
- 版本发布更新 `package.json`、README、版本更新和本文基线。
- 演示种子会清空数据，只允许在开发/测试环境执行。
