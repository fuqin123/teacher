## v0.6.1（2026-11-24）—— 修复 HTTP 部署下“登录成功仍提示请先登录”

### 现象

Docker 部署切到 HTTP + IP 访问后，账号密码正确、登录接口返回 200，但进入看板立即出现红色「请先登录」，各列表与图表均为空。

### 原因

`express-session` 的 Cookie 在 `COOKIE_SECURE=true`（或 `NODE_ENV=production` 且未显式配置）时带 `Secure` 属性。浏览器只在 HTTPS 下保存 `Secure` Cookie，HTTP 访问时该 Cookie 被丢弃，于是登录后的每个请求都缺少会话，返回 401「请先登录」；登录本身是成功的，所以现象具有迷惑性。

### 修复

1. **服务端自动推导 Cookie 安全属性**（`apps/api/src/main.ts`）：未显式配置时按 `APP_ORIGIN` 协议判断（http → `Secure=false`，https → `true`）；若显式配置 `true` 但 `APP_ORIGIN` 是 http，强制关闭并输出告警日志，避免再次踩坑。
2. **编排默认值**：`docker-compose.yml` 的 `COOKIE_SECURE` 默认改为空，交由上述逻辑推导，HTTPS 部署仍按 `APP_ORIGIN` 正确开启。
3. **前端统一处理会话失效**：`AuthGuard` 的 401 返回 `code: AUTH_REQUIRED`；前端在 401 时清理登录态、`queryClient.clear()` 并跳转 `/login?expired=1`，登录页显示「登录状态已失效，请重新登录」；看板不再渲染“请先登录”红条，冷启动未登录时不显示“已失效”。
4. 基础数据页/看板等处的加载错误不再把 401 当业务错误展示。

### 验证

- 模拟 `NODE_ENV=production` + `COOKIE_SECURE=true` + `APP_ORIGIN=http://10.113.1.238:8083`：启动日志输出告警，`Set-Cookie` 不含 `Secure`，HTTP 登录后接口正常。
- 登录后在数据库清空会话表并点击导航：页面跳转 `/login?redirect=/base-data&expired=1`，登录卡片显示「登录状态已失效，请重新登录」。
- 冷启动直接访问受保护页面：跳转登录页且不显示“已失效”提示。
- `pnpm typecheck`、`pnpm build` 通过。

## v0.6.0（2026-11-24）—— AI 配置界面化与真实成绩表适配

### 背景

v0.5.0 的 AI 配置只能通过环境变量设置，管理员在服务器上改 `.env` 并重启容器才能生效；同时导入器只支持单行表头，而学校实际导出的成绩表是「标题行 + 科目/分数/校名次/班名次 三级合并表头」，直接上传会把第 4 行当成数据行。本版本解决这两个阻塞点，并按真实表结构重做模板。

### 新增

1. **AI 配置由管理员在界面维护**
   - `app_settings.ai_config` 存储启用开关、Base URL、模型、超时与加密后的 API Key；
   - Key 使用 AES-256-GCM 加密（密钥由 `SESSION_SECRET` 经 scrypt 派生），任何接口只返回 `sk-a••••3456` 形式的掩码；
   - 新增 `GET/PUT/DELETE /admin/ai-settings` 与 `POST /admin/ai-settings/test`；
   - 连通性测试先 `GET /models`，不支持时回退一次最小 `chat/completions`，失败信息按 401/403/404/429/5xx/超时分类给出；
   - 配置读取顺序：数据库（界面）→ 环境变量；界面保存后导入立即生效，无需重启；
   - 变更写审计（不含 Key 明文），支持「恢复环境变量配置」。

2. **兼容学校导出的多级表头**
   - 识别 2~3 行表头：一级为科目、二级为「分数 / 校名次 / 班名次」，合并单元格的科目名向前填充后拼接为 `语文-分数`、`语文-校名次`；
   - 数据从表头之后开始读取，并逐行记录真实 Excel 行号，校验提示不再偏移；
   - `学校`、`班级`、`序号`、原始名次列一律忽略；`总分-分数` 识别为原始总分并忽略（系统按科目重算）；
   - 科目别名匹配：`道法`/`政治`/`思想品德` → 道德与法治；
   - CSV 保留 UTF-8/GBK 自动识别，xlsx/xls 走二进制读取。

3. **标准模板重做**
   - `GET /imports/template` 生成 xlsx：标题行（合并）、学号/姓名/各科分数/总分/班级排名/年级排名、两行示例 + 一行缺考示例；
   - 第二个 sheet「填写说明」列出学号规则、缺考写法、排名列可留空、可直接上传学校导出表等 6 条；
   - 列宽按学号/姓名/分数分别设置，前端「下载标准模板」改为调用该接口。

### 变更

- `ParsedImportResponse` 新增 `headerRows`，导入向导显示「已识别第 3–4 行表头」；
- 前端设置页 AI 卡片改为完整表单（开关、Base URL、模型、超时、Key、测试连接、保存、恢复环境变量）；
- 版本号升至 0.6.0。

### 验证

- 使用真实文件名 `142_学生成绩(1).xlsx`（3 行合并表头、28 列、52 行）验证：识别表头第 3–4 行、数据 52 行、`考号`→学号、8 个科目列命中、`总分/校名次/班名次` 全部忽略。
- 构造带 `总分/班级排名/年级排名` 列的 3 行文件走完上传→映射→校验→入库：忽略 3 个排名列，写入 24 条成绩（含 1 条缺考），看板自动计算总分与班级/年级名次，缺考学生不参与排名。
- AI 配置：默认读环境变量；界面保存后 `source=database`、Key 显示掩码；`/models` 测试返回「连接成功，可用模型 2 个」；清空后回退环境变量。
- `pnpm typecheck`、`pnpm build` 通过。

### 已知问题

- 只读取工作簿的第一个 sheet；多 sheet（一班一表）仍不支持。
- 表头行仍由规则定位（前 20 行打分），极端排版可能需要人工确认。
- 导入时原始名次列被忽略，系统按成绩重算排名，不保留学校原始名次。

## v0.5.0（2026-11-24）—— AI 识别、基础数据维护与湖南初中口径

### 背景

v0.4.0 把数据库收敛到本机 SQLite 后，阻碍教师日常使用的两点变得突出：不同学校、不同年级的成绩表列顺序与命名各不相同，纯规则映射需要人工逐列调整；学期、班级、学生名单等基础数据此前只能靠种子数据或数据库工具维护。本版本补上 AI 表头识别与管理员维护界面，并把科目口径与界面文案统一到湖南初中。

### 新增

1. **AI 表头识别（OpenAI 兼容接口）**
   - `apps/api/src/modules/imports/ai-mapping.service.ts`：调用 `/chat/completions`，`response_format=json_object`、`temperature=0`、默认 25 秒超时；
   - 输入仅表头、3 行脱敏样例（姓名替换为“学生”、学号保留前 4 位）、科目清单与班级/年级名称；
   - 输出列映射、考试名称/类型/日期、科目满分，经 `aiMappingResponseSchema` 校验并过滤越界列、未知科目后才合并进映射；
   - 新增 `GET /imports/ai-status`、`POST /imports/:id/ai-suggest`；上传后若 AI 已启用则自动识别，也可在映射页手动“重新 AI 识别”；
   - 超时、HTTP 错误、JSON 非法、结构不符一律回退到规则建议，接口仍返回 200 并给出可读原因；
   - 每次调用写 `import.ai_suggest` 审计（模型、列数、token 用量、失败原因）。

2. **管理员基础数据维护**
   - 新增 `AdminModule`（`/admin/*`），全部接口仅管理员可用，写操作落审计；
   - 学期：新增/修改/设为当前学期（自动取消其他当前学期）；
   - 年级：按学期建档，层次 7/8/9 对应初一/初二/初三；
   - 班级：选择年级、填班级组（自动 find-or-create）、指定班主任、排序；
   - 科目：新增/修改、启停用、默认满分、排序，代码唯一；
   - 学生：新增（同时建当前学期归属）、改名/改学号/改状态、调班；
   - 前端「基础数据」页改为可编辑，新增/编辑通过弹窗完成，非管理员仍为只读。

3. **CSV 编码识别**
   - `ExcelParserService` 先按 BOM → UTF-8 → GBK 顺序解码 CSV，再交给 SheetJS 解析；
   - 修复 WPS/Excel 导出的中文表头被当作单字节编码读取导致的乱码（乱码会连带让规则与 AI 映射全部失效）。

4. **班级看板底部**
   - 分数段分布与临界生卡片等高，图表高度随卡片自适应，底部改为信息行，消除图表下方大片空白；
   - 分数段柱状图底部留白、刻度斜排、柱顶数值与整数刻度，修复刻度文字被裁切。

5. **湖南初中口径**
   - 种子科目改为语文 120、数学 120、英语 120、物理 100、道德与法治 100、历史 100、生物 100、地理 100，共 1,008 条成绩；
   - 登录页、侧栏、导入说明、设置页、基础数据页文案统一为湖南初中语境。

### 变更

- 版本号升至 `0.5.0`；`pnpm-lock.yaml` 无新增依赖（AI 走内置 `fetch`）。
- `.env.example`、`docker-compose.yml` 增加 `AI_ENABLED` / `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` / `AI_TIMEOUT_MS`。
- 设置页新增 AI 状态卡（是否启用、模型、接口地址、降级说明）。

### 验证

- `pnpm typecheck`、`pnpm build` 通过。
- 模拟 OpenAI 兼容服务验证：上传 CSV → AI 返回列映射与考试信息 → 前端自动填入映射表并显示“AI 识别结果”、AI 说明与置信度。
- 关闭模拟服务验证降级：`ai-suggest` 返回 `applied=false` 与“AI 服务不可用，已回退到规则建议”，HTTP 200，导入不受影响。
- 基础数据：管理员新增学期/科目/班级/学生、修改科目与班级、学生调班均通过；班主任访问 `/admin/*` 返回 403；重复学年学期、非法学年格式返回中文校验提示。
- 编码：UTF-8 与 GBK CSV 的中文表头均正确解析并命中规则映射。
- 看板：1440×900 下分数段刻度完整可见，分布与临界生卡片等高，无多余留白。

### 已知问题

- AI 仅识别列结构与考试元信息，不处理多 sheet / 一科一表；表头行仍由规则定位。
- 映射模板复用尚未实现，相同格式重复导入仍会调用 AI。
- SQLite 单写者模型：同时运行多个 API 实例写入时可能短暂 `database is locked`（仅测试时出现，单实例部署不受影响）。

## v0.4.0（2026-11-24）—— 数据库改为本地 SQLite

### 背景

v0.3.0 的部署形态是 PostgreSQL + API + Web 三容器。实际使用范围确定为“一位教师、一个班级”，成绩数据总量在万级以内，独立数据库容器对教师本机是额外负担：需要 Docker、需要维护数据库密码、备份要依赖 `pg_dump`。本版本把数据库收敛为一个 SQLite 文件，业务功能与接口行为不变。

### 变更

1. **数据存储**
   - `schema.prisma` 的 `provider` 由 `postgresql` 改为 `sqlite`；
   - 去掉 `@db.Decimal`、`@db.Date` 等 PostgreSQL 原生类型，分数继续使用 Prisma `Decimal` 标量；
   - 删除旧的 PostgreSQL 初始化迁移，重建 `init_sqlite` 迁移；
   - 数据库文件：开发为 `apps/api/data/scorelens.db`，容器内为 `/app/data/scorelens.db`。

2. **会话存储**
   - 移除 `connect-pg-simple`、`pg` 及对应类型包；
   - 新增 `apps/api/src/common/prisma-session.store.ts`，会话写入 `user_sessions` 表，重启服务后登录态保留；
   - 不再引入 `connect-sqlite3` / `better-sqlite3` 等原生 SQLite 驱动，避免教师机器上的编译依赖。

3. **脚本与运维**
   - 删除 `db:up` / `db:down`（不再有数据库容器）；
   - 新增 `db:reset`（重置并重新迁移）、`db:backup`（`VACUUM INTO` 一致性快照）；
   - 种子脚本的 `TRUNCATE ... CASCADE` 改为按外键顺序 `deleteMany` 事务。

4. **部署**
   - `docker-compose.yml` 去掉 `postgres` 服务与 `POSTGRES_PASSWORD`；
   - 数据库与上传文件共用 `app_data` 卷，备份快照通过绑定挂载直出到宿主机 `./backups`；
   - 根目录 `.env.example` 同步删除数据库密码项。

5. **查询适配**
   - 名单搜索移除 PostgreSQL 专属的 `mode: 'insensitive'`，依赖 SQLite `LIKE` 的默认行为。

### 验证

- `pnpm typecheck`、`pnpm build` 通过；`prisma migrate deploy` 在空目录下自动创建数据库与目录。
- 种子重建 42 名学生、3 场考试、630 条成绩。
- `/api/v1/health` 返回 `db=up`；登录、`/auth/me`、名单搜索、看板统计（Decimal 读取与聚合）、导入上传→映射→校验→入库全链路通过。
- 重启 API 后同一 Cookie 仍可访问 `/auth/me`，确认会话持久化。
- `pnpm db:backup` 生成一致性快照成功。

### 已知问题

- SQLite 为单写者模型，多人并发导入需要迁移到 PostgreSQL。
- Docker 镜像未在本版本内重新构建验证（编排改动已通过 `docker compose config` 校验），Ubuntu 实机验收仍按部署文档执行。
- 自动化测试仍未补齐。

## v0.3.0（2026-11-24）—— Ubuntu Docker 全栈部署

3. **Ubuntu 部署文档**
   - Docker 安装、环境变量、HTTPS、防火墙和验收清单；
   - 演示数据、备份恢复、升级回滚和故障排查；
   - 明确数据库与 API 端口不暴露公网。

### 变更

- `pnpm db:down` 改为只停止 PostgreSQL，避免误停整个应用栈。
- README、项目架构、功能清单和开发记录同步当前版本与部署基线。
- 界面版本角标更新为 `v0.3.0`。

### 修复

- Caddyfile 统一为 `caddy fmt` 可接受的缩进，消除启动格式警告。
- 上传文件恢复命令改为在 API 停止时使用一次性容器，避免 `docker compose exec` 无法执行。

### 验证

- `docker compose config --quiet`、`pnpm typecheck`、`pnpm build` 通过。
- API、Web 镜像构建成功，PostgreSQL、API、Web 三个容器健康检查通过。
- 自动迁移、Caddy 健康检查、登录会话、SPA 深层路由回退和上传目录写入通过本机 Docker 验证。
- Ubuntu 24.04 实机验收仍需按部署文档执行。

### 已知问题

- 自动化测试仍未补齐。
- Prisma 在 slim 镜像中可能输出 OpenSSL 检测警告；当前迁移和运行验证正常，后续继续做镜像加固。

## v0.2.0（2026-11-23）—— 下拉、留白与图表动效

### 背景

v0.1.0 使用原生 `<select>`，在不同浏览器中样式不一致；内容区最大宽度 1320px，在 1920px 屏幕上两侧留白偏大；ECharts 虽然配置了图表，但入场动画不明显。参考 `E:\teacher_class\app` 的 shadcn/ui Select / Combobox 方案与图表封装策略，在不引入额外 UI 依赖的前提下做本项目适配。

### 新增

1. **AppSelect 组件**（`apps/web/src/components/AppSelect.vue`）
   - 基于 Teleport 的 fixed 浮层，自动计算上下空间，弹层始终位于触发框外侧，不再遮挡按钮；
   - 弹层宽度与触发框对齐并支持最小宽度；
   - 可搜索；键盘 ↑ / ↓ / Enter / Esc 操作；选中项勾选高亮；滚动跟随；
   - 支持 `size="sm"`、禁用、提示文字（hint）、空状态；
   - 使用原型设计令牌与轻量缩放/淡入动画。

2. **学生快速定位**

### 修复

- ECharts 封装在 `setOption` 之后立即 `ResizeObserver.observe`，首次回调会触发 `resize()`，导致入场动画被直接压到终态。现改为尺寸判重（宽高变化 > 1px 才 resize），初始回调忽略。
